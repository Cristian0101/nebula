# Official provider authentication

Expand an instance in **Settings → Providers** and choose **Check status**. Login controls require **Manage access** (`access:write`) on that execution environment. Ordinary execution and provider/MCP credentials do not gain account-management authority. Existing clients without this scope need an appropriately authorized connection; Nebula never upgrades their permissions automatically.

The displayed environment and instance identify where authentication happens. Signing in on your Mac does not authenticate a separate remote host. Complete a browser callback on the correct machine, or use the provider's device-code ceremony when supported.

| Provider      | Supported behavior                                                                                                                                                                | Limits                                                                                                                                                                                       |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Codex         | Managed App Server ChatGPT browser login and device code; provider-hosted completion page; correlated completion, cancellation and fresh `account/read` with `refreshToken: true` | Unsupported protocol methods/parameters remain unsupported. No OAuth implementation, token import or API-key collection.                                                                     |
| Cursor        | Official configured CLI `login`, using `NO_OPEN_BROWSER=1` for a private browser handoff; fresh existing readiness/ACP probe after completion                                     | Uses the existing ACP runtime. `agent` can name another product, including Grok; executable names are not interchangeable.                                                                   |
| Claude        | Guided official `claude auth login` in a user-controlled terminal, then Check status; fresh `claude auth status --json` independently of SDK initialization                       | Use the instance's configured executable, environment and Claude configuration directory on that host. Nebula does not launch Claude OAuth, harvest setup tokens or replace the SDK runtime. |
| Other drivers | Existing readiness controls                                                                                                                                                       | Registration does not imply interactive login support.                                                                                                                                       |

API keys, external tokens, cloud-provider credentials and config helpers can take precedence over subscription authentication. Detected environment overrides block new managed ceremonies until the user reviews them. Claude's guidance also calls out config helpers; Nebula does not extract their values. Login never removes an override, logs out shared provider applications, or selects API billing as a fallback.

Authentication, account identity, billing route, entitlement, model catalog and runtime preflight remain independent E1 facts. Status is provider-reported evidence; it does not prove unlimited usage, model entitlement or a completed inference request. Cursor login does not prove unified X Subscription migration or standalone Claude/GPT subscription coverage. Claude eligibility and limits depend on current provider terms. Verification never sends a paid turn.

Attempts remain in volatile server memory and expire after five minutes. Concurrent starts on one instance reuse the attempt. Cancel requires the matching attempt ID; stale cancellations/completions cannot replace a newer attempt. Instance replacement and host restart invalidate lifecycle state. Deliberately configured instances may still share a provider-owned account store.

Login URLs/codes are private ephemeral data, discarded after completion, cancellation, failure or expiry. Never copy them into Task/Mission history, logs, screenshots or bug reports. Process failures return fixed reasons rather than raw provider errors.

## E3 contract

Managed Codex login currently requires the default local App Server launch configuration. Custom launch arguments remain available to the existing runtime, but login through Nebula is unsupported for those configurations: use the official CLI with the same configuration, then refresh readiness. Authentication never copies arbitrary configuration values into process arguments or silently changes the execution configuration. Shell-only launchers likewise do not gain managed login support.

Feature-detect `ExecutionEnvironmentCapabilities.providerAuthentication`. Use the existing authenticated environment transport to call `server.providerAuthentication` with exact `environmentId`, `instanceId` and `begin / status / cancel / refresh`. Begin selects an advertised `browser / device-code / terminal` ceremony. Cancel requires the current `attemptId`. No caller-supplied command, executable, path, Task or permission change is accepted.

Keep responses in volatile UI memory. Poll status during an active attempt; refresh requests fresh account/readiness evidence and completes guided terminal verification. Consume the existing provider snapshot subscription for E1 changes. Preserve capability/lifecycle/readiness distinctions, scope denial, host identity, transport loss, expiry, instance replacement, API overrides and failed verification. Never persist ceremony data or infer entitlement.
