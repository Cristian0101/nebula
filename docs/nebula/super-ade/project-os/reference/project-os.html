A

Overview: what's happening, what needs me, where to resume

The execution context comes first, then Needs you sorted by decision class, then Resume and Live now side by side. The launch bar's send button is the only solid violet control. No hero, metrics or decorative glow in an active project.

  • Needs you is one pure derivation over the checkout's snapshot: thread approval and input flags, Mission checkpoints and run attention, Task attention, review verdicts, Integration conflicts and E1 readiness. Each action opens the existing surface.
  • Interrupted turns appear here even though the sidebar does not flag them today. Stale provider readiness never does.
  • Launch bar creates a draft on this checkout and moves the text into the real composer. It is not a second composer runtime.
B

Branches & Worktrees

Checkouts first, because only checkouts have live status, processes, sessions and PRs. Branches without a checkout show only ref facts. HEAD, commit time, detached and missing worktrees need the additive vcs.listWorktrees query and ref fields (E4.3); until then those cells are hidden, never faked.

C

Worktree safety: select, open, switch

Selecting never mutates. Opening never changes an existing checkout. Switching always runs a fresh server assessment, lists each blocker with its evidence and a link, and prefers Open in a new worktree. There is no stash, force, discard, kill or "Switch anyway" anywhere.

Removal eligibility (read-only in E4)

A separate, high-consequence workflow. E4 shows fresh eligibility only. Removal stays in the existing Task and Integration cleanup flows.

D

Project workspaces in the Workbench

A workspace is a named Terminal Workspace layout, not a Git worktree. Each pane header states what it is attached to, so a second view of the same Chat Thread, a separate provider CLI session, another worktree, a Task and another environment never look alike.

E

Project navigation sidebar

The active project expands to its checkout line and destinations. Other projects stay single rows with environment glyphs, a badge for decisions that block work, and a live dot. Hover or focus a collapsed project for a summary; it never shifts the layout. Chevrons and the inbox filter work in these frames.

G

Responsive: 390 to 2560

The same components at each width. Under 768px the sidebar becomes a sheet and a destination bar is the only tab row; the launch bar docks to the bottom; branch rows become two lines. At 2560 content stays capped and the Workbench spreads into three columns.

H

Dark and light

Both modes are first-class. Use the Palette control to compare the proposed Nebula Ion with the shipped default theme. E4 renders through theme roles only and does not change the default theme.

I

Notes boundary

Where Notes will live once their backend ships: a sidebar destination, a Pinned notes card and the composer's @Notes entry. Dashed outlines mark future placement only. Nothing here renders in the product before the backend exists, and Notes never become Mission memory.
